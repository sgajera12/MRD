## Overview

MRD-offroad is a **synthetic**, multimodal dataset for perception in unstructured, off-road environments. It is generated by a real-time mixed-reality co-simulator built in **Unreal Engine 5** at the Autonomous Vehicle Mobility Institute (AVMI), Worcester Polytechnic Institute. As a simulated vehicle drives through procedurally generated off-road terrain, the system records synchronized **RGB images, LiDAR point clouds, semantic RGB images, semantic LiDAR point clouds, vehicle states (position, velocity), and sensor calibration parameters** — all in standard **ROS 2 bag** format with **automatic ground-truth annotations** (no manual labeling).

Because ground truth is produced automatically, the dataset scales rapidly: at a **10 Hz** recording rate the simulator generates on the order of **10⁵ synchronized, annotated samples in roughly tbd hours** of simulation, with full control over terrain geometry, lighting, weather, and obstacle distribution.

**Sim-to-real validation.** A SegFormer-B2 model trained *only* on tbd synthetic images produced reliable semantic segmentation on the real-world **RUGD** dataset **without any fine-tuning**, correctly identifying classes such as sky, tree, bush, ground, rock, and stump — evidence of the simulator's photometric and structural realism.

### Generation Pipeline
- **Engine:** Unreal Engine 5 (developed/profiled on UE 5.4).
- **Terrain:** procedurally generated — macro-scale landscape synthesized by a **VAE trained on real-world elevation data**, micro-scale roughness added via a **multifractal Weierstrass–Mandelbrot (W–M) noise model**; heightmaps imported as UE5 landscape actors. Terrain domain spans **1 × 1 km²**.
- **Terrain materials:** an automatic texturing system blends surface types based on terrain attributes (elevation, slope, local geometric variation).
- **Obstacles:** a configurable **Procedural Content Generation (PCG)** pipeline places rocks, bushes, trees, and other assets; placement is conditioned on terrain slope, elevation, and designated traversability class. Obstacles use accurate collision geometry (for realistic LiDAR returns/occlusion) and high-quality textures (for photorealistic camera images).
- **Domain control:** environment conditions — terrain geometry, lighting, weather, obstacle distribution — are fully configurable for scenario diversity and repeatable collection.
- **Annotation:** semantic labels and precise vehicle states are generated automatically during simulation.

### Simulated Sensor Setup
All streams are time-synchronized and recorded at **10 Hz** in ROS 2 bag format; calibration (intrinsics/extrinsics) is exact and exported from the simulator.

| Sensor | Model / basis | Key specs | Rate |
|---|---|---|---|
| Camera (RGB) | Pinhole model; intrinsics matched to a Carnegie Robotics **MultiSense S27**; radial + tangential distortion; UE5 photometric pipeline (auto-exposure eye-adaptation, filmic tone mapping, Sky Atmosphere + Volumetric Clouds) | FOV computed analytically from intrinsics; resolution TBD | 10 Hz |
| LiDAR | Ray-casting spinning-LiDAR model (structurally consistent with a mechanical LiDAR); physical counterpart is a **Velodyne VLP-16** | Configurable beam geometry, FOV, and scan rate; **geometric returns only** (intensity/reflectance not yet modeled — future work) | 10 Hz |
| Vehicle state | Physics-based 6-DoF vehicle-dynamics model | position, velocity | 10 Hz |

### Real-World Counterpart
A custom electric 4WD UGV serves as the physical twin (for mixed-reality experiments and optional fine-tuning): exteroceptive sensing via a **Velodyne VLP-16** LiDAR and a **Carnegie Robotics MultiSense S27** stereo camera; proprioception via US Digital optical encoders and a **VectorNav VN-300 GNSS/INS**; compute on dSPACE MicroAutoBox III (perception/planning, Ubuntu) and MicroAutoBox II (control); ROS 2 + Intempora RTMaps middleware.

## Getting Started

### Requirements
```bash
# TODO: pin versions
python >= 3.9
# ROS 2 (Humble or later) to read the bags
pip install -r requirements.txt   # numpy, opencv-python, open3d, pyyaml, ...
```

### Read a ROS 2 bag
```bash
# Inspect topics (RGB, LiDAR, semantic RGB, semantic LiDAR, vehicle state)
ros2 bag info rosbags/<run>.db3
```

### Load an extracted sample
```python
import cv2, numpy as np

img   = cv2.imread("MRD-offroad/00000/image/000000.png")
label = cv2.imread("MRD-offroad/00000/image_label_id/000000.png", cv2.IMREAD_GRAYSCALE)
cloud = np.fromfile("MRD-offroad/00000/lidar_bin/000000.bin", dtype=np.float32).reshape(-1, 4)  # x,y,z,intensity
pts   = np.fromfile("MRD-offroad/00000/lidar_label/000000.label", dtype=np.uint32)              # per-point class id

print(img.shape, label.shape, cloud.shape, pts.shape)
```

### LiDAR–camera fusion (as used in the AVMI perception stack)
Project LiDAR into the segmented image, then transfer labels back to 3D:
1. Transform points: LiDAR → Vehicle → Camera → Optical frame.
2. Depth filter: drop points behind the camera (Z < 0) and too close (Z < 0.1 m); keep only points visible to the camera.
3. Project with the pinhole model: `u = fx*X/Z + cx`, `v = fy*Y/Z + cy`.
4. Assign each projected point the class of the underlying segmented pixel → semantically labeled 3D point cloud.
